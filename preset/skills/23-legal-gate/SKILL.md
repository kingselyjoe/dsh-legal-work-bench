# 门禁审批（legal-gate）

## 功能

work-bench 的人批机制：关键节点（接案/策略/定稿/结案）由 AI 提交申请 → **律师人工审批** → 记录决定。这是"对外动作必须人批"铁律的落地（吸收 dsh-law 的 gate_request + decide 模式）。

## 门禁类型

| 门禁 | 触发 | 审批要点 |
|---|---|---|
| 接案（intake） | 新案件创建/收案时 | 利益冲突、案源确认、受理范围 |
| 策略（strategy） | 诉讼/合同策略确定时 | 策略方案、风险接受度（对照画像） |
| 定稿（filing） | 文书过双闸门后送审时 | 最终稿确认、格式/份数/期限 |
| 结案（closure） | 案件办结时 | 全部事项完成、归档、费用结算 |

## 流程

```
AI 提交申请（gate/requested）
   ├─ title: <门禁标题>
   ├─ type: intake/strategy/filing/closure
   ├─ summary: <申请摘要（含依据/双闸门结论）>
   └─ 落盘 matters/<案件ID>/gates.md（status: pending）
        ↓
律师人工审批（人批，AI 不能自批）
   ├─ approve → status: approved + 决定时间 + 审批人
   └─ reject → status: rejected + 原因 + 修改指引
        ↓
记录入 events.md + 16-legal-audit-log（审批人/时间/决定）
```

## 输出格式（gates.md）

```markdown
# 门禁记录：<案件ID>
| 门禁 | 类型 | 状态 | 申请时间 | 摘要 | 审批人 | 审批时间 | 决定 |
|---|---|---|---|---|---|---|---|
| 收案确认 | intake | ✅ approved | ... | ... | <律师> | ... | 通过 |
| 策略确认 | strategy | ⏳ pending | ... | ... | — | — | 待审 |
```

## 执行规则

1. **AI 不能自批**：门禁状态只能由律师审批动作改变；AI 提交申请后必须等待人工决定
2. **结案必须人工**：任何 AI 流转不得进入"已结案"（对齐 22-legal-matter 状态机）
3. **审批留痕**：审批人、时间、决定必须记录（人批 = 有责任主体的动作）
4. **双闸门前置**：定稿门禁（filing）必须在 04 事实核验 + 05 合规审查通过后提交
5. **拒绝闭环**：reject 必须带原因与修改指引，AI 据此修改后重新提交
6. **提醒**：pending 门禁进入提醒（对齐 dsh-law 紫标思路，对接 18-docket-watcher 的 severity）

## 本技能不做什么

- 不自动通过/拒绝门禁
- 不代替律师做实质判断（审批是人的责任）

## 质量检查

- [ ] AI 申请与人工审批分离
- [ ] 结案有人工记录
- [ ] 审批留痕完整（人/时间/决定）
- [ ] filing 门禁有双闸门前置
