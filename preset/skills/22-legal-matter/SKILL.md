# 案件管理（legal-matter）

## 功能

work-bench 的案件管理层：把每个案件建成一个 **Matter**——标准目录结构 + 状态机 + 事件记录（只追加），让案件状态可看、可查、可回溯。

> 设计吸收：dsh-law 的 case 数据模型 + 六列看板 + 八级目录；dsh-legal 的只追加事件模型。

## 创建案件（Matter）

案件落在 `matters/<案件ID>/`（案件 ID = `m-<日期>-<序号>`，如 `m-20260817-001`）。创建时自动建立**八级目录**：

```
matters/<案件ID>/
├── 01_收案与委托/     # 委托合同、授权书、收案登记
├── 02_客户材料/       # 客户提供的原始材料（只读，不改动原件）
├── 03_证据/           # 证据整理、证据清单、三性分析
├── 04_法律检索/       # 检索记录、类案、法条
├── 05_文书草稿/       # 草稿与版本
├── 06_定稿与提交/     # 已过双闸门的定稿、提交记录
├── 07_庭审/           # 庭审准备、庭审笔录要点
└── 08_结案归档/       # 结案报告、归档
```

## 案件字段（state.md）

每个案件维护 `state.md`（核心档案）：

```markdown
# Matter: <案件标题>
- 案件ID: m-20260817-001
- 类型: 诉讼/仲裁/合同审查/尽调/咨询...
- 案号/仲裁号: <如已有>
- 法院/仲裁委: <如已有>
- 承办法官/仲裁员: <如已有>
- 当事人: <甲方/乙方 列表>
- 状态: 待接案/调查取证/策略制定/文书起草/待定稿送审/已结案
- 工作模式: 全流程辅助/咨询接待/按需协作/关闭
- 绑定会话: <DSH 会话 ID>（每案独立会话，cwd = 案件目录）
- 关键期限: <指向 18-docket-watcher 的期限表>
- 创建时间: <时间戳>
```

## 六列状态机（看板流转）

```
待接案 → 调查取证 → 策略制定 → 文书起草 → 待定稿送审 → 已结案
```

- 流转用 `transition` 记录：`state.md` 追加 `- <时间>: <由谁(人/AI)>: <阶段A> → <阶段B>`
- **结案必须人工**（AI 不可直接流转到"已结案"，须过 23-legal-gate 的结案门禁）
- 每个阶段对应目录：策略制定 ↔ 04 法律检索 / 文书起草 ↔ 05-06 / 待定稿送审 ↔ 06（定稿须过双闸门）

## 事件记录（只追加）

案件所有变更写入 `events.md`（只追加、不覆盖；更正产生新条目 `fact/revised`）：

```markdown
- evt-<序号>: <时间>: <动作> | <由谁> | <详情> | <来源/依据>
```

允许的事件：matter/created、party/added、fact/added|revised、deadline/added、evidence/added|status、claim/added|linked、doc/drafted|versioned、gate/requested|decided、transition、delivery/approved。

## 执行规则

1. **只追加不覆盖**：案件状态、事实、事件只用追加；写错产生修订事件，历史保留（对齐 dsh-legal 原则）
2. **每案一目录**：案件文件全部在案件目录内，不外散
3. **原件只读**：客户材料放 02 不改动，加工产物放 03-08
4. **保密**：案件目录含敏感信息，禁止写入公开仓库（.gitignore 已忽略 matters/）
5. **绑定会话**：每案建议绑定独立 DSH 会话（cwd = 案件目录），便于上下文隔离
6. **联动 16-legal-audit-log**：案件重大动作入审计链

## 本技能不做什么

- 不自动创建/删除案件文件之外的系统对象
- 不自动结案（必须人工 + 门禁）
- 不把案件内容输出到公开渠道
