# 冷启动画像访谈（cold-start-interview）

## 功能

为律师/法务建立**实践画像**：你是谁、做什么业务、风险偏好如何、合同立场是什么、什么情况要上报。这是 work-bench 一切技能的**前置条件**——没有画像，技能只输出泛化内容。

## 画像存储

- 个人画像：`~/.dsh/legal-workbench/<域>/profile.md`（散文形式，非 YAML，便于 Agent 直接理解）
- 机构画像：`~/.dsh/legal-workbench/<域>/company-profile.md`（律所/公司层面的共享立场）
- 画像不写入任何仓库（见 .gitignore：profiles/ 已忽略）

## 运行模式

| 模式 | 适用 | 耗时 |
|---|---|---|
| 快速（默认） | 想尽快开始 | 2 分钟 |
| 完整 | 希望画像全面 | 15 分钟 |
| `--redo` | 重跑全部问题 | — |
| `--side` | 补充某个侧面（如新增业务领域） | — |

支持暂停恢复：回答中途离开，用 `[PENDING]` 标记未完成项，下次继续。

## 访谈提纲

### 第 1 步：角色确认
- 你是：执业律师 / 可对接律师的非律师（法务/顾问）/ 无律师背景
- 执业领域（多选）：商事合同 / 劳动 / 诉讼 / 知产 / 婚姻家事 / 刑事 / 公司法务…
- 服务对象：个人客户 / 企业客户 / 混合

### 第 2 步：执业场景
- 主要工作类型：合同审查起草 / 案件代理 / 常年顾问 / 非诉项目…
- 常用文件类型：合同/诉状/尽调报告/法律意见书…
- 平均案件量/周期（用于期限监控配置）

### 第 3 步：风险偏好（六维评价）
请用户对以下六维打分（1 保守 - 5 激进）：
1. 责任上限接受度（愿意接受的赔偿封顶比例）
2. 条款谈判硬度（坚持底线 vs 灵活让步）
3. 新法适用倾向（审慎观望 vs 主动采用）
4. 争议解决偏好（仲裁 vs 诉讼；管辖地偏好）
5. 数据合规强度（最低合规 vs 高规格合规）
6. 时间/质量取舍（快速交付 vs 严谨交付）

### 第 4 步：合同立场（核心——种子文件反推）
**首选方式（种子文件反推）**：请用户提供 5-10 份已签署的代表性合同（脱敏后），Agent 从实际签署条款反推真实立场：
- 责任限制条款：责任上限通常约定为合同额的多少比例
- 赔偿条款：是否接受惩罚性赔偿/间接损失排除
- 数据处理（DPA）条款：是否接受默认 DPA
- 期限条款：合同期限/续约/提前终止习惯
- 管辖与争议解决：常选仲裁委/法院
反推后与用户确认："我理解你的立场是 X，对吗？"

**备选方式（问答）**：无法提供种子文件时，按上述维度逐项问答。

### 第 5 步：上报矩阵
| 情形 | 处理 |
|---|---|
| 涉及金额超过 <阈值> | 上报合伙人/主管 |
| 条款突破画像底线 | 标记 + 上报 |
| 新客户/新行业首次 | 上报 |
| 时间不足 <阈值> 交付 | 上报并调整期望 |

### 第 6 步：生成画像
汇总输出 `profile.md`，包含：角色、领域、场景、六维风险画像、合同立场（种子反推结论 + 确认记录）、上报矩阵、默认偏好。完成后告知用户："画像已建立，可以开始工作了。"

## 执行规则

1. **遇 [PLACEHOLDER] 即 STOP**：用户没回答的必填项不臆测，标记后继续或停止。
2. **种子文件优先**：有已签合同一定用反推方式（真实行为 > 口头偏好）；反推结论必须让用户确认。
3. **保密**：种子文件中的客户名、金额、主体信息脱敏后使用；画像含敏感信息，只存本机。
4. **可增量**：`--side` 支持后续补充领域；画像变更用追加方式（`profile/revised`），保留历史。
5. **画像过期**：超过 180 天或用户业务变化时，提示重跑。

## 本技能不做什么

- 不做法律分析（只收集偏好）
- 不把种子文件内容写入仓库
- 不替用户决定立场（只反推 + 确认）
- 不生成泛化画像（每个画像必须来自用户输入）

## 质量检查

- [ ] 六维风险画像完整（或标注 PENDING）
- [ ] 合同立场有来源（种子反推记录或问答记录）
- [ ] 上报矩阵已确认
- [ ] 画像已落盘 profile.md
