# 合规质量审查闸门（legal-compliance-review）

## 功能

对已过事实核验的交付物做**执业合规 + 文书质量**双检查，输出审查报告。这是双闸门第二道：关键违规默认阻断，只输出问题清单。

## 输入

- 交付物 + 事实核验报告（04 通过）
- 交付类型：提交法院 / 发送客户 / 发送对方 / 律所内部 / 公开发布
- 案件上下文（当事人、相对方、管辖法院/仲裁委）

## 一、执业合规检查

1. **利益冲突**：本案相对方/关联方是否与已代理案件冲突（提示人工核验，不自动判断）
2. **保密义务**：交付物是否含客户秘密/个人信息未脱敏（内部 vs 外部场景分别检查）
3. **承诺结果**：无"保证胜诉/必赢/稳拿赔偿"等表述（违规则 ❌）
4. **程序合规**：提交法院的文书——管辖/期限/份数/签章要求是否满足；对方法件——送达与回复期限
5. **执业边界**：无越权代理、无冒充官方、无虚假资质表述
6. **敏感信息**：涉及在办案件公开传播需人工确认（与 dsh-legal-ip 联动时）

## 二、文书质量门禁

1. **结构完整**：必备部分齐全（标题/当事人/事实/理由/依据/请求/落款）
2. **引用规范**：法条引用格式统一（《法规名称》第 X 条）、案号规范
3. **逻辑一致**：请求与事实、理由与依据一一对应，无自相矛盾
4. **格式要求**：目标机构格式要求（法院/仲裁委模板、字号、页数）
5. **语言规范**：无口语化/情绪化表述、无错别字、术语准确

## 输出格式

```markdown
# 合规质量审查报告：<交付物名称> ｜ 审查时间：<时间戳>
## 一、执业合规
| # | 检查项 | 结果 | 说明 |
|---|---|---|---|
| 1 | 利益冲突 | ✅/⚠️ | 需人工核验：... |
| 2 | 保密脱敏 | ✅/❌ | ... |
| 3 | 承诺结果 | ✅/❌ | ... |

## 二、文书质量
| # | 检查项 | 结果 | 说明 |
|---|---|---|---|
| 1 | 结构完整 | ✅/❌ | ... |

## 三、结论
- ✅ 通过：可进入人工审批与交付
- ✏️ 需修改：列出修改点（轻微问题）
- ⛔ 阻断：关键违规，**禁止交付**，只输出问题清单
```

## 执行规则

1. **Fail Closed**：关键违规（承诺结果、未脱敏客户秘密、程序硬伤）→ 阻断，不得交付。
2. **分级**：轻微（措辞/格式）→ 需修改；关键（合规红线/程序）→ 阻断。
3. **场景区分**：提交法院 > 发送对方 > 发送客户 > 内部——不同场景检查深度不同（法院文件程序要求最严）。
4. **人批前置**：审查通过 ≠ 自动交付；交付仍须律师人工批准（门禁治理，对齐 dsh-law 的 gate 模式）。
5. **与审计链**：审查报告 + 审批记录写入 `matters/<案件ID>/verification/`（只追加）。

## 本技能不做什么

- 不自动发送/提交任何文件（必须人批）
- 不替代律师判断利益冲突的实质
- 不因审查通过就免除律师责任

## 质量检查

- [ ] 双闸门顺序正确（先 04 事实核验，后本环节）
- [ ] 执业合规六项 + 质量五项全覆盖
- [ ] 关键违规已阻断并给出清单
- [ ] 交付场景区分检查
- [ ] 报告与审批记录已入审计链
