# 审计链（legal-audit-log）

## 功能

work-bench 的审计机制：每次工作产出生成**不可否认的审计记录**（只追加），形成可追溯、可复盘的审计链。这是差异化能力之一（dsh-law 只有简单 history/feed）。

## 触发

- **自动**：领域技能交付时（04/05 双闸门通过后）自动追加审计条目
- **手动**：用户要求审计查询/导出时

## 审计条目字段

```markdown
- 条目ID：audit-<时间戳>-<6位随机>
- 时间戳：ISO 8601
- 案件/项目：matters/<案件ID>/
- 产出物：<文件名>
- 输入材料：<文件清单 + SHA-256 哈希>
- 来源版本：法源（法规库/北大法宝/元典 + 版本/日期）
- 技能版本：<技能名 + 版本>
- 模型版本：<模型名 + 版本>
- 工具调用：<使用的工具/数据源清单>
- 验证结果：04 事实核验（通过/待核验项）＋ 05 合规审查（通过/修改/阻断）
- 审批记录：<审批人 + 时间 + 决定>
- 前序条目：<上一条 audit-id>（形成链）
```

## 存储

- 位置：`matters/<案件ID>/audit/audit-log.md`（只追加，不覆盖）
- 完整性：每条记录前序条目 ID + 内容哈希，形成哈希链；重要交付物附审批人电子签名记录

## 输出格式（审计查询）

```markdown
# 审计查询：<案件/时间范围>
| 条目ID | 时间 | 产出物 | 输入哈希 | 验证 | 审批 |
|---|---|---|---|---|---|
| ... | ... | ... | ... | ✅/⚠️ | <人>/<时间> |
```

## 执行规则

1. **只追加**：审计记录不可覆盖/删除；更正产生新条目
2. **必填字段**：时间戳、输入哈希、验证结果、审批记录缺一不可
3. **哈希链**：每条记录含前序 ID，防止中间篡改
4. **敏感脱敏**：审计记录中的材料内容脱敏（只留哈希与文件名，不留正文）
5. **版本绑定**：记录所用法源/技能/模型版本，支持版本漂移审计

## 本技能不做什么

- 不记录完整思维链（只记录可验证事实与流程）
- 不自动审批（审批是人的动作）

## 质量检查

- [ ] 必填字段齐全
- [ ] 哈希链连续
- [ ] 敏感信息脱敏
